# reminder-timezone — 2026-07-01

Deferred item picked up: study reminders were compared against the **server** hour,
so a user in another timezone got the email at the wrong local time. Now each user
has a timezone and the reminder fires at their **local** hour.

## What changed

### Backend (`3454839`)
- **Schema**: new `user_profile.reminder_tz` (IANA string, nullable). Added via the
  **first real incremental Alembic migration** `9413f2a93a7e` (down_revision =
  baseline `8326c9605659`) — autogenerated, applied **in place** on the running
  Postgres volume with **no data loss** (verified: `alembic_version` advanced and
  all 3 existing accounts survived).
- `repositories.due_reminders(now_utc, default_tz)` — for each user with a reminder,
  compute the local time from `reminder_tz` (falling back to `default_tz`, then UTC;
  invalid zones fall back too), and return them due only when the local hour matches
  and they haven't been emailed on their **local** calendar date. Each due row now
  carries its local `date` so `mark_reminder_sent` records the right day per zone.
- `update_profile` accepts `reminderTz`; `account._public` returns `reminderTz`.
- `routes/internal.run_reminders` — computes `now` in UTC (with `?now=<iso>` override
  for tests/replays) and passes `cfg.REMINDER_DEFAULT_TZ`; marks each user sent with
  their own local date.
- `config.REMINDER_DEFAULT_TZ` (default `Asia/Jakarta`) for users without a zone.
- `requirements.txt`: `tzdata` so `zoneinfo` resolves on slim Linux + Windows.

### Frontend (`9195118`)
- `RemindersSection` adds a **time-zone dropdown** (curated IANA list). The browser's
  zone is auto-detected (`Intl…timeZone`) and pre-selected — prepended to the list if
  not already there. Saves `reminderTz` alongside the time; hint now reads "fires at
  that time in your time zone". `AccountUser.reminderTz` + `accountProfile` typed;
  i18n `set.timezone` + updated `set.reminderHint` (EN+ID).

## Notes / caveats
- Behavior change for pre-existing reminders (reminder_tz NULL): they now use the
  default zone (**Asia/Jakarta**) instead of the server clock — more correct for this
  owner, but a shift for anyone who was implicitly relying on server time.
- The scheduler still runs hourly, so reminders are hour-granular (minutes ignored),
  unchanged.
