# Cleanups Design: M4 + L1–L5 (Batch 3)

**Status:** proposed → awaiting approval · **Date:** 2026-07-05 · **Epic:** Post-audit cleanups (final batch)

## Goal
Close the remaining low-severity audit items: one interactive-a11y gap (M4) plus
i18n, dead-code, code-quality, and auth-hardening tidy-ups (L1–L5). All low-risk,
additive or removal-only; no schema/contract change.

## Findings addressed
- **M4** — `Card variant="interactive"` used as a click target ([Home.tsx:135](../../../web/src/components/menu/Home.tsx) `onClick={() => setView(skill)}`) is a `<div>` with no `role="button"`, `tabIndex`, or key handler → not keyboard-accessible.
- **L1** — [Home.tsx:177](../../../web/src/components/menu/Home.tsx) hardcodes `"Day "` (i18n key `session.day` already exists: EN "Day" / ID "Hari").
- **L2** — [Settings.tsx:57](../../../web/src/components/settings/Settings.tsx) language button reads `"Indonesia"`; endonyms are intentionally untranslated, but the label should read `"Bahasa Indonesia"`.
- **L3** — dead `label` fields in `Sidebar.tsx` NAV_ENTRIES and `Home.tsx` SKILLS (never rendered; UI uses `t("nav." + view/skill)`).
- **L4** — [llm.py:227](../../../api/app/services/llm.py) `except (KeyError, Exception)` — `Exception` already subsumes `KeyError`.
- **L5** — [account.py](../../../api/app/routes/account.py) `google_login` trusts `claims["email"]` without checking `email_verified`; register still enumerates accounts (accepted — see non-goals).

## Design
- **M4 (reusable fix in `Card`).** When `variant="interactive"` AND an `onClick` is
  provided, `Card` renders with `role="button"`, `tabIndex={0}`, a `focus-visible`
  ring, and an `onKeyDown` that fires `onClick` on Enter/Space. Non-interactive cards
  are unchanged. Fixes every interactive card in one place.
- **L1.** Replace the literal with `{t("session.day")} {m.dayTarget}`.
- **L2.** Change the button text to `Bahasa Indonesia` (still an endonym, clearer).
- **L3.** Remove the unused `label` property + its type from both arrays.
- **L4.** Narrow to `except Exception:`.
- **L5.** In `google_login`, only trust the Google email when
  `claims.get("email_verified")` is truthy; otherwise pass an empty email to
  `upsert_google_user` (prevents linking to an unverified address). Sign-in by
  `google_sub` still works. Register enumeration left as-is (see non-goals).

## Non-goals
- **Register enumeration (L5b):** not changed — removing the "already registered"
  message degrades signup UX; the endpoint is already rate-limited (5/min). Documented
  as accepted risk.
- No visual restyle; no new deps; no schema change.

## Testing
- **M4 (vitest):** an interactive `Card` with `onClick` exposes `role="button"`,
  is focusable, and fires `onClick` on Enter. Existing `shell.test.tsx` (Home) stays green.
- **L5 (pytest):** `google_login` with `email_verified=false` creates/links the user
  by `sub` **without** adopting the unverified email; with `email_verified=true` the
  email is adopted. (Extend `test_google_auth.py` or add a case.)
- **L1/L2/L3/L4:** covered by `tsc --noEmit`, existing web tests, and the full pytest
  suite (no behaviour change).
- Gates: `cd web && npx tsc --noEmit && npm test`; `cd api && pytest -q`.

## Boundary
Frontend: `Card.tsx`, `Home.tsx`, `Settings.tsx`, `Sidebar.tsx` (+ 1 test).
Backend: `llm.py`, `account.py` (+ test). No infra/schema change.
