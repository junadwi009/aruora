# 02 — IELTS Scoring Integrity

## Goal
Make every numeric score mathematically correct, reproducible, versioned, and represented as an **estimate** unless generated by an official IELTS process.

## WS02 ownership
Primary files expected:
- `api/app/domain/scoring.py`
- `api/app/domain/leveling.py`
- `api/app/domain/placement.py`
- relevant API schemas/routes only when required by scoring metadata
- `api/tests/test_placement_scoring.py`
- new scoring/calibration tests

Avoid authentication, Redis, CI, and deployment edits in this workstream.

## Task WS02-01 — Fix official half-band rounding
Current pattern `round(mean * 2) / 2` is unsafe because Python uses ties-to-even.

Implement a named function with explicit IELTS semantics. Required regression cases:
- 6.25 → 6.5
- 6.75 → 7.0
- 6.125 → 6.0
- 3.875 → 4.0
- already-half/whole values remain unchanged

Use decimal-safe or explicit quarter handling; do not rely on incidental float rounding.

**Acceptance:** tests mirror official IELTS examples and pass.

## Task WS02-02 — Stop treating CEFR as exact equivalence
The reviewed `ielts_to_cefr()` uses hard thresholds. IELTS itself states IELTS and CEFR serve different purposes and do not have one-to-one equivalence; a 6.5 result can be borderline around C1.

Change the product contract from exact `cefr` truth to one of:
- `cefrApprox` with documented mapping source and borderline state; or
- a range/alignment object, e.g. `{level:"B2/C1", confidence:"borderline"}`.

Maintain backward compatibility during migration if the frontend expects `cefr`. Add a deprecation path rather than silently changing JSON meaning.

**Acceptance:** public UI/API documentation says CEFR alignment is approximate; tests cover boundary cases.

## Task WS02-03 — Separate official rules from AI estimates
Create a scoring metadata envelope persisted with every AI-scored attempt:
- `score_method` (`deterministic`, `llm_estimate`, `audio_estimate`, etc.)
- `score_version`
- `model_provider`
- `model_id`
- `prompt_version`
- `rubric_version`
- `calibration_version`
- `created_at`

Do not rely on historical model aliases remaining stable.

## Task WS02-04 — Criterion weighting and task semantics
Validate that Writing Task 1 vs Task 2 criteria names are correct in UI and persistence. Preserve the four official criterion categories but avoid claiming that an LLM rating is an examiner rating.

For Speaking, do not compute an examiner-like overall score from a fabricated pronunciation criterion. Until `06_SPEAKING_ASR_AUDIO_PIPELINE.md` is validated, return a text-based estimate with pronunciation `unassessed` or clearly approximate and exclude it from any result labeled “full Speaking estimate”.

## Task WS02-05 — Calibration harness contract
Define a frozen calibration dataset format without committing copyrighted official test content or private user data:
```json
{
  "sample_id": "anon-001",
  "skill": "writing",
  "task_type": "task2",
  "prompt_license": "internal-or-permitted",
  "response": "...",
  "human_scores": [{"rater":"R1","overall":6.5}],
  "adjudicated_score": 6.5
}
```

Required metrics for model/prompt promotion:
- exact-band agreement;
- within-0.5 agreement;
- mean absolute error;
- weighted kappa or another justified ordinal agreement metric;
- repeated-run stability;
- subgroup error analysis where lawful/appropriate.

No model/prompt update reaches production solely because qualitative examples “look better”.

## Task WS02-06 — Copyright/trademark-safe rubric material
Audit `api/app/services/prompts.py`, fixtures, screenshots, and tests for long verbatim official descriptors/sample-test content. IELTS.org states its website material and trademarks are protected and commercial reuse generally requires permission.

For public commercial deployment choose one:
1. obtain documented permission/licence; or
2. replace copied material with original paraphrased internal rubric text derived from publicly described criteria, reviewed for scoring validity; and link users to official sources rather than republishing protected material.

Do not use official logos without permission.

## ARUORA Readiness integration

ARUORA may show target gap and a readiness summary, but readiness must not disguise an AI estimate as a second official score.

Until a validated readiness formula exists, prefer:

```text
Target: 7.0
Current estimate: 6.0
Biggest gap: Writing
Recent evidence: 3/4 skills assessed
```

If `Readiness %` is later introduced, persist its formula/version and document that it is a product heuristic rather than an IELTS probability.

Aura may explain scoring evidence but must not say or imply:
- “your official band is ...”;
- “an IELTS examiner would definitely give ...”;
- “you are guaranteed to reach ...”.

## Product wording requirements
Allowed direction:
- “AI-estimated band”
- “practice score estimate”
- “based on IELTS-style criteria” only after legal wording review
- “not an official IELTS result”

Do not use:
- “official score”
- “certified IELTS examiner” for the model
- “guaranteed band”
- claims that a CEFR mapping is exact

## Exit criteria
- Official rounding regression suite passes.
- CEFR representation is explicitly approximate.
- Scoring metadata/version is persisted.
- Speaking cannot present transcript-only pronunciation as fully assessed.
- Calibration file format + promotion threshold are documented and runnable.
- Legal/IP audit ticket exists for any retained official text/material.
