# 06 — ARUORA UI Design System

## 1. Product UI Principle

ARUORA UI must feel like:

> **a calm preparation workspace with a living companion**

not:

> a game dashboard.

---

# 2. Home Information Priority

Recommended order:

1. Destination
2. Readiness
3. Today's Recommendation
4. Weakest Skill
5. Progress
6. Deadline
7. Flow
8. Community / Study Pod

---

# 3. Recommended Home Hero

Example:

```text
Good evening.

IELTS target
7.0

Current estimate
6.0

Readiness
68%

Biggest gap
Writing

46 days remaining

[ Start Today's Training ]
```

Aura may appear nearby with one sentence.

---

# 4. Readiness

Readiness should be more prominent than streak.

Readiness may combine:

- current estimated performance
- target gap
- recent consistency
- skill completion
- trend

Do not imply scientific precision if model is heuristic.

---

# 5. Flow

Replace flame-heavy streak identity.

Use:

> **Flow**

Examples:

- 7-day Flow
- Flow active
- Continue your Flow

Visual motif:

- orbit
- ring
- subtle luminous path

---

# 6. Cards

Cards:

- warm neutral surface
- subtle border
- restrained elevation
- 18px default radius
- content-first

Avoid:

- heavy shadow
- gradient every card
- oversized icon badge on every module

---

# 7. Buttons

Primary:

- Aura Violet
- cream/white text depending contrast
- 14px radius
- clear action copy

Secondary:

- neutral surface
- border
- Ink text

Use gradient only for rare major moments.

---

# 8. Form Controls

Must feel serious enough for scholarship/professional audience.

Avoid playful illustrated form controls.

Use:

- clean labels
- large touch targets
- clear selected state
- compact explanations

---

# 9. Placement Journey

Preferred visual sequence:

```text
Goal
↓
Target
↓
Deadline
↓
Placement
↓
Result
↓
Program
↓
Today's Training
```

Aura should progressively appear after enough context is known.

---

# 10. Placement Result

Priority:

1. Estimated overall level
2. per-skill level
3. gap to target
4. weakest skill
5. recommended next action
6. disclaimer that score is estimated

Avoid overwhelming users with too many charts.

---

# 11. Skill Color Usage

Do not create totally independent brand colors per skill.

Use contextual accents only.

Example:

- Reading: violet
- Listening: blue
- Speaking: coral
- Writing: lavender / violet
- Success across all: mint

Core UI remains ARUORA.

---

# 12. Community UI

Community should not begin as a social feed.

Use:

- Study Pool
- Study Pod
- partner availability
- peer review request
- skill-focused room

Example:

```text
Study Pod
IELTS 6.0 → 7.0
Writing focus
November exam
6 learners
```

---

# 13. User Profile

Recommended fields:

```text
Current estimate
Target
Destination
Exam month
Weakest skill
Strongest skill
Flow
Meaningful sessions
Open to practice
```

Avoid follower/following metrics.

---

# 14. Aura Placement

Aura appears when she adds context.

Good:

- result
- recommendation
- explanation
- empty state
- matching
- reminder
- achievement

Avoid:

- floating permanently over content
- blocking important controls
- repeated decorative mascot

---

# 15. Responsive Priority

Mobile:

- one clear action
- one primary readiness summary
- Aura compact
- avoid desktop dashboard squeezed into phone

Desktop:

- main learning column
- secondary deadline/progress rail
- Aura near contextual recommendation

---

# 16. Dark Mode

Dark mode may emphasize:

- Midnight surfaces
- cream text
- restrained violet
- aurora achievement moments

Do not make dark mode look like neon cyberpunk.

---

# 17. Accessibility

Required:

- keyboard navigation
- visible focus
- screen-reader labels
- touch target >= 44px where practical
- reduced motion support
- color-independent feedback
- readable error messaging

---

# 18. Existing Pilot Migration Principle

Existing IELTS Coach functionality should be retained where useful.

Rebrand should prioritize:

1. visual token migration
2. terminology migration
3. Aura integration
4. readiness hierarchy
5. destination-driven onboarding
6. community-ready data structure

Do not rewrite working core logic only for visual reasons.
